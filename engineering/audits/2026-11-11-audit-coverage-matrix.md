# Audit Coverage Matrix (evidence-based, 2026-11-11)

Sources: `AJ/aj/audit.py` (append-only JSONL, file lock, `redact`, `MemoryAuditSink`/`JsonlAuditSink`), `aj/orchestrator.py`, `aj/journal.py`, `aj/receipts.py`, `aj/task.py`, `aj/memory.py`, `aj/lease.py`, `aj/recovery.py`, `aj/scheduler.py`, `aj/calling.py`. Audit writes are **not transactionally atomic** with task/journal/receipt SQLite/state writes.

## Policy classification
- **BEST-EFFORT DIAGNOSTIC:** operational/diagnostic events where loss should not block unrelated safe work (e.g. some progress/memory-summary diagnostics), but failure must be observable. *Current implementation generally records to sinks without a uniform mandatory-vs-best-effort policy engine — classification below is required target/evidence-based assessment, not fully enforced.*
- **MANDATORY SECURITY AUDIT:** authorization allow/deny, approval request/decision, refusal of protected operation, and security-relevant policy enforcement evidence. If such evidence cannot be persisted, the protected operation **must not proceed**. *Gap: explicit block-on-audit-failure behavior for all protected operations is **VERIFICATION REQUIRED / PARTIALLY IMPLEMENTED**.*
- **TRANSACTIONAL STATE EVIDENCE:** state transitions and side-effect commit evidence (task/journal/receipt/idempotency) that must remain consistent or be recoverable via explicit strategy (journal/receipt reconciliation). No outbox implemented; existing journal/receipt/task stores are the recovery substrate.

## Mandatory audit failure behavior (2026-11-11 F4 continuation, PARTIALLY IMPLEMENTED/VERIFIED)

- **Policy mechanism (minimal, no parallel framework):** `aj/audit.py` `AuditLog.record(..., mandatory=False)` now treats sink write exceptions as: **MANDATORY** → exception propagates (caller must block protected side effect / fail truthfully, no false persisted-success event), **BEST_EFFORT (default)** → failure is captured observably (`[aj.audit]` stderr + recent non-persisted marker) and does not break caller. `JsonlAuditSink.write` raises on I/O failure (no silent swallow) so policy can be enforced. `AuditLog.try_record` added for structured result handling. Backward-compatible: existing non-mandatory calls remain best-effort.
- **Enforced handle boundaries (VERIFIED by controlled sink-failure injection, real `Aj.handle` paths, `tests/test_f4_audit_enforcement.py`):** `awaiting_approval` (CONFIRM), `policy_denied` (DENY), and pre-execution `authorized` (before `_execute`) are recorded as `mandatory=True`; on persistence failure the path returns structured `StorageError` failure (`FAILED`), **protected side effect not executed** (`actions.calls == []`), and no false persisted "authorized"/decision event is written. Best-effort diagnostic failure (`task_received`) does **not** block a safe permitted read-only execution.
- **Ordering evidence (handle authorized path):** task becomes AUTHORIZED and authorization context saved → mandatory `authorized` audit persisted → lease/journal/memory scheduling evidence → `_execute`. If mandatory audit fails, execution is not reached.
- **Not yet enforced/proven:** mandatory classification/enforcement for all other security-relevant emitters (retry/recover/resume scheduler promotions/refusals, calling, adapter-specific decisions, every refusal path), transactional ordering guarantees across independent audit/journal/task/receipt stores, outbox/atomic commit (not implemented), retry/duplicate-evidence hardening beyond covered paths, and full cross-process persisted-readback proof for every event category. **PARTIAL / VERIFICATION REQUIRED**.
- **Failure behavior summary:** mandatory persistence failure blocks protected operation at enforced boundaries and reports accurate structured failure; best-effort failure remains observable and non-blocking for safe unrelated work.
